# ゲート2 チェックリスト: ユーザーストーリー作成（レシート金額抽出・生活費入力の詳細化）

- 対象成果物: `docs/01-user-stories.md`
- 対応する作業指示書: `docs/work-orders/2-stories-order.md`
- 使用スキル: `gate-check`（判定レポートは `docs/gates/gate-2-report.md` に作成）
- 判定方針: 1項目でもFAILなら総合不合格（軽微なら「条件付き合格」とし条件を明記）。根拠のないPASSは禁止、必ず `docs/01-user-stories.md` の該当箇所（見出し・行）を確認して判定する

| # | チェック項目 | 確認方法（根拠の探し方） |
|---|---|---|
| 1 | 全ストーリーが `## US-<番号>: <タイトル> [Must\|Should\|Could\|Won't]` の見出し形式になっている | 各見出しを目視確認。番号の重複・欠番がないこと |
| 2 | 全ストーリー本文が「〜として、〜したい。なぜなら〜だから。」形式で、ペルソナ・目的・価値の三要素を含む | 各ストーリー本文を確認 |
| 3 | 冒頭にペルソナ定義一覧があり、本文中のペルソナがそこに定義されたものと一致する | 文書冒頭とストーリー本文を突合 |
| 4 | 全ストーリー（Won'tを除く）に `**受け入れ基準**` のチェックボックスがあり、各条件が数値・具体的状態など検証可能な表現である（「適切に」「高速に」「使いやすく」等の曖昧語がない） | 受け入れ基準を1件ずつ確認し、曖昧語をgrep等で検索 |
| 5 | 末尾にMoSCoW集計表があり、本文中の各ストーリーのタグ数と集計値が一致する | 集計表とストーリー一覧のタグ数を突合 |
| 6 | 要件確認ノート（`docs/00-requirements-notes.md`）の要件一覧・Won't一覧・「既存の生活費手入力を残す」の計11項目が、すべて何らかのストーリー本文／受け入れ基準／Won'tエントリに反映されている（作業指示書3節の対応表を用いて1項目ずつ突合） | 対応表の11項目を1つずつ`docs/01-user-stories.md`内で検索し、反映箇所を特定できるか確認 |
| 7 | Won't項目に理由が明記されている（要件確認ノートのWon't一覧の理由と矛盾しない） | Won'tエントリの理由文を要件確認ノートと突合 |
| 8 | ストーリーが画面遷移・DBスキーマ・APIルート・HTTPメソッド・テンプレート名などゲート4（設計）以降の実装詳細に踏み込んでいない（What/Whyにとどまる） | 受け入れ基準にURL・SQL・関数名等が含まれていないか確認 |
| 9 | 既存ドメイン用語・アーキテクチャと矛盾する記述がない（特に `LivingExpense.category`（既存5値固定）と新しい「小分類」を混同・断定していない、`Money`/`YearMonth` の制約と矛盾しない） | `docs/basic_design.md`・`app/domain/model/living_expense.py` と記述を突合 |
| 10 | NFR相当の内容（利用頻度、復旧目標、運用費上限、想定件数など）がユーザーストーリーとして書かれておらず、ゲート3に先送りされている | ストーリー本文・受け入れ基準にNFR的な数値基準が紛れ込んでいないか確認 |

## 不合格時の差し戻し

- 差し戻し先: builder-docs
- 差し戻し方法: 上表でFAILとなった項目番号と、該当箇所（見出し・行）、修正すべき内容を明記して再依頼する
