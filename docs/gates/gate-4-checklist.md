# ゲート4 チェックリスト: 基本設計（レシート金額抽出・生活費入力の詳細化）

- 対象成果物: `docs/03-basic-design.md`
- 対応する作業指示書: `docs/work-orders/4-design-order.md`
- 使用スキル: `gate-check`（判定レポートは `docs/gates/gate-4-report.md` に作成）
- 判定方針: 1項目でもFAILなら総合不合格（軽微なら「条件付き合格」とし条件を明記）。根拠のないPASS禁止

| # | チェック項目 | 確認方法 |
|---|---|---|
| 1 | doc-templateの章立て(1.技術スタック/2.ディレクトリ構成/3.画面設計/4.モジュール・データ設計/5.外部連携/6.トレーサビリティ表)が揃っている | 見出しを目視確認 |
| 2 | すべての画面・モジュールにID(SCR-xx, MOD-xx)が振られ、重複・欠番がない | ID一覧を確認 |
| 3 | US-01〜US-11すべてが設計要素（SCR/MOD）に反映されている（Won'tは「対応しない設計である」ことの明記でよい） | トレーサビリティ表とUS一覧を突合 |
| 4 | NFR-01〜09すべてが該当モジュール・画面設計で言及されている | トレーサビリティ表とNFR一覧を突合 |
| 5 | 3-1の設計論点（既存`LivingExpense.category`と新しい小分類の関係）が断定的に決定され、根拠が明記されている（先送り・両論併記になっていない） | 該当節を確認 |
| 6 | 貼り付け一括登録（US-03）の入力形式が1つ具体的に決定されている | 該当節を確認 |
| 7 | 4層アーキテクチャの依存方向・Port命名規則(`SqlAlchemy<名前>Repository`)・DI規約(`provide_<名前>`)に矛盾しない | 既存コード規約と突合 |
| 8 | Won't確定済み(US-05〜US-11)と矛盾する設計要素がない(外部API・スマホ対応・自動バックアップ等) | 各設計要素をWon't理由と突合 |
| 9 | DB設計がNFR-08(想定件数100件規模)を前提にし、過剰設計になっていない | DB設計節を確認 |
| 10 | 曖昧語(「適切に」「高速に」「使いやすく」)が使われていない | grep確認 |
| 11 | 末尾にUS⇔NFR⇔SCR/MODのトレーサビリティ表がある | 文書末尾を確認 |

## 不合格時の差し戻し

- 差し戻し先: builder-docs
- 差し戻し方法: FAILとなった項目番号・該当箇所・修正内容を明記して再依頼
