## 要件一覧(優先度付き)

| 要件 | MoSCoW | 判定理由 |
|---|---|---|
| レシート画像のアップロード・保存（ファイルシステム＋DBパス参照） | Must | これがないと教師データが作れず、企画の最小ラインを満たせない |
| 品目単位（品目名・金額・小分類）での生活費入力 | Must | 小分類集計・教師データ双方の前提データ。これがないと目的（家計の見直しデータ化）が達成不能 |
| 読み取り結果（品目一覧）の貼り付け一括登録 | Should | 効率化の要素。1件ずつの手入力でも運用は回せるため代替可能だが、週3回以上の利用頻度を考えると効率化の価値は高い |
| 小分類別の月次集計表示 | Must | 「食品／生活用品等に分けたい」という目的そのもの |
| 画像とデータのバックアップ強化（既存pg_dump超の対応） | Won't | ユーザーが既存運用のままでよいと判断 |
| カード請求の自動読取・CSV連携 | Won't | 別機能として切り離し、今回スコープ外と明示 |
| フェーズ3（OCR/ML自動抽出） | Won't | 教師データ100件到達後に改めて企画判断する |
| アプリからの外部AI API呼び出し | Won't | コスト0円の制約を満たすため、当面は手動運用に留める |

## Won't(やらないこと)一覧 — 必ず理由を付ける

| やらないこと | 理由 |
|---|---|
| カード請求の自動読取・CSV連携 | 別途独立した機能として検討予定。今回はレシート（現金支出）に限定してスコープを絞るため |
| フェーズ3: OCR/MLによる自動抽出 | 教師データが目安100件貯まってから、精度実現性を含めて改めて企画判断する。現段階で着手すると過剰投資になるため |
| アプリへの外部AI API組み込み | 運用費0円の制約を満たすため。組み込む場合は将来的にグローバルルール上のユーザー確認（有料サービス契約）が必要になる |
| スマホからの画像アップロード対応 | 利用者（本人）がPCのみで運用する前提のため、画面幅対応のコストをかけない |
| 品目名の月次画面への一覧表示 | 集計は小分類単位で十分。品目名はDB上のデータ（教師データ用）として保持するに留める |
| 新規の定期バックアップ強化 | 既存のpg_dump手動運用で実害なしとユーザーが判断したため |
