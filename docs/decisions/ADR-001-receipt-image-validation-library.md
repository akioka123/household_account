# ADR-001: レシート画像の検証に Pillow を採用する

- 日付: 2026-08-25 / 状態: 承認済

## 背景(Why)

US-01（レシート画像のアップロード・保存）の受け入れ基準は「画像として読み込めないファイルがアップロードされた場合、保存は行われず利用者にエラーが表示される」ことを求める。拡張子やContent-Typeのチェックだけでは、拡張子を偽装したファイルや破損した画像データを検出できない。実際にピクセルデータとしてデコード可能かどうかを検証する必要がある。

## 決定(What)

画像デコード検証ライブラリとして **Pillow**（PyPI: `Pillow`、import名 `PIL`）を `requirements.txt` に追加する。アップロードされたファイルは `PIL.Image.open()` で開き `verify()` を呼び出すことで、デコード可能な画像データかどうかを検証する。検証に失敗した場合は保存を行わずエラーを返す。

## 実施方法(How)

- `app/infrastructure/storage/filesystem_receipt_image_storage.py`（MOD-10、詳細は `docs/03-basic-design.md` 4章）で `PIL.Image.open(io.BytesIO(data)).verify()` を用いて検証する。
- `requirements.txt` に `Pillow>=10.0.0,<12.0.0` を追加する（実装はゲート5で行う）。
- Pillow は無償のオープンソースライブラリ（PSFライセンス系）であり、pip インストールのみで完結する。外部API・SaaSへの通信は発生しないため、NFR-06（月次運用費0円）・US-08（外部AI API呼び出しWon't）と矛盾しない。

## 採らなかった選択肢と理由(Why not)

- **マジックバイト（先頭数バイト）のみのチェック**: JPEG/PNGのシグネチャ確認だけでは、シグネチャは正しいが本体データが破損しているファイルを検出できず、US-01の受け入れ基準（「読み込めないファイル」の確実な検出）を満たせないため採らない。
- **画像処理を行わずファイル拡張子のみで判定**: なりすまし・誤ったファイルを保存してしまうリスクが高く、US-01の意図（教師データの原本を確実に保存する）に反するため採らない。
- **外部の画像検証API・クラウドサービスの利用**: 月次運用費0円の制約（NFR-06）およびローカル運用の方針に反するため採らない。

## しないこと(スコープ除外)

- 画像のリサイズ・圧縮・EXIF除去等の加工は行わない（US-01は保存・参照のみを要求しており、加工は本機能のスコープ外）。
- OCR・画像分類等の解析処理は行わない（US-07 Wontのスコープ）。

## 再検討条件

- フェーズ3（US-07、OCR/ML自動抽出）に着手する際、画像の前処理（リサイズ等）が必要になった場合は本ADRを再検討する。
