# receipt-parse: レシート解析

household_account のフェーズ2運用（`docs/03-basic-design.md` 5章）に対応するスキル。レシート画像1枚から、生活費タブの「貼り付けで一括登録」（TSV形式、`app/domain/service/receipt_paste_parser.py` が解析する仕様）にそのまま使える品目データを作る。

## 手順

1. 画像を読み、店舗名・日付・各品目名・各金額を書き出す
2. 各品目を小分類に分類する。**分類の判定基準は品目名の意味だけでなく、レシートに印字された軽減税率区分を検算に使う**: 「外8%対象」は食品（`食品`）、「外10%対象」は非食品（`生活用品`）。household_account の小分類は現状この2種のみ（`app/domain/model/living_expense_item.py` の `LIVING_EXPENSE_ITEM_SUBCATEGORIES`）。この2種以外を作らない
3. 金額の検算: 各品目金額の合計（割引適用後）が「小計」と一致するか確認する。一致しない場合、読み取りミスがあるとみなし、どの行が疑わしいかを特定する（不鮮明な文字・指で隠れている箇所・改行で品目名と金額が離れている箇所を優先的に疑う）
4. 複数個割引（例:「1コ99、2コ180」のような値引き行）は、household_account の品目データが金額0以上しか持てない（`Money`の制約）ため、独立した行にはできない。値引き後の実purchase額を対象品目に案分して反映する（例: 99円×2点が180円になる割引なら、90円・90円として2行に分ける）。案分した旨を出力時に明記する
5. 読み取りに自信が持てない行（不鮮明・被写体の指で隠れている・金額と品目名の対応が推測になる等）には確信度（高/中/低）を付け、低い場合はユーザーに実物との突き合わせを依頼する。数値を確信なく捏造しない
6. 結果を以下の2つの形式で出力する
   - 表形式（品目名・金額・小分類・確信度）: 人が読んで確認するため
   - コードブロック内にTSV（品目名`\t`金額`\t`小分類、ヘッダ行なし、小分類は`食品`/`生活用品`の日本語ラベル）: そのままアプリの貼り付け欄にコピペできる形式
7. 検算が合わなかった場合や低確信度の行がある場合は、その旨を明記してからTSVを出す（黙って通さない）

## 出力後の案内

- TSVは生活費タブ→「貼り付けで一括登録」にそのまま貼り付けられる旨を伝える
- 画像自体は「レシートを画像付きで登録」からアプリにアップロードすると、読み取り結果とペアで保存され、フェーズ3（将来のOCR/ML自動化）の教師データになる。ユーザーがまだ画像をアプリにアップロードしていないようであれば、この一言を添える（毎回長々と説明しない、一言で十分）

## やらないこと

- 小分類を`食品`/`生活用品`以外に増やさない（アプリの固定リストと不整合になるため）
- 金額を推測だけで断定的に埋めない。検算不一致・低確信度は必ず申告する
- 会員番号・電子マネー番号などの個人情報らしき文字列を出力に含めない（品目データに不要なため）
